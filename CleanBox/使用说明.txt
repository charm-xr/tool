清理匣 CleanBox 2.0
本地软件扫描、卸载与占用文件处理

【启动】
双击本文件夹内的 CleanBox.exe。适用于 Windows 10/11 x64，使用 .NET Framework 4.8。
本机已验证运行，不需要另装 Python、Node.js 或 SDK。整个文件夹可以保留在 D 盘。
普通扫描不要求管理员；需要卸载全机软件、处理受限目录或登记重启后删除时，可点左下角“管理员模式”，由 Windows 显示权限提示。

【2.0 界面】
左侧切换软件管理、文件解锁、操作记录；软件选中后在右侧查看详情与操作。
左下角可切换深色 / 浅色外观、紧凑 / 舒适列表；设置保存在 data/ui-preferences.txt。
顶部“扫描软件”展开基础扫描、全盘发现、指定文件夹扫描和导出清单。
Ctrl + F 搜索软件；F5 基础扫描；Esc 取消当前可取消的任务。
绿色软件候选仅表示未找到登记记录，可能包含辅助程序或卸载快捷方式，需要先核对。
小窗口会隐藏列表中的版本列；完整版本、路径和来源仍可在右侧详情查看。

【软件扫描】
启动时读取 32/64 位的全机、当前用户卸载记录，当前用户 Microsoft Store / MSIX 包，以及当前用户和公共开始菜单、桌面快捷方式。
“全盘发现”允许选择本机固定磁盘，递归搜索 EXE；“扫描文件夹”可指定绿色软件、游戏或工具目录。
磁盘和快捷方式结果都是候选项。系统组件也会显示并标记，但不允许本工具卸载。
相同登记记录、相同程序路径会去重；同目录同产品名也合并。不会因为某个父目录已登记，就隐藏它内部发现的全部其他程序。
可以按名称、发布者、路径搜索，按来源筛选，并导出当前筛选结果为 CSV。

扫描范围和限制：
没有任何工具能保证识别所有软件。本工具不通过安装软件、运行候选程序或触发 MSI 修复来扫描。
磁盘发现只认 EXE；纯脚本、仅有 DLL 的组件、打包归档和未挂载的磁盘不作为独立软件自动识别。
不加载其他用户的离线注册表、不枚举其他用户的商店注册，也不扫描驱动/服务清单。
跳过 Windows 系统保护目录、WindowsApps、当前用户的商店数据目录、目录链接、无权限目录，以及 .git、node_modules、.venv、__pycache__ 等依赖目录。
可访问的磁盘程序文件可以补充登记列表未覆盖的候选。程序文件夹位置有时由图标/卸载器推定，删除前必须核对。
无权限或长路径等原因可能导致漏扫，扫描日志与状态会标明可识别的问题。

【正常卸载与残留】
先在软件清单选择软件，点“正常卸载”。传统软件由原卸载器处理；弹出确认会展示将执行的入口。
MSI 使用 Windows Installer 的交互式卸载；商店软件使用 Windows 自身的包管理，仅卸载当前用户。
本工具不静默卸载，不会因发现软件就执行任何卸载动作。原卸载器启动成功不等于卸载完成。
卸载完成后点“检查残留”。只列出安装位置及名称完全匹配的 AppData/ProgramData 目录，并逐个进入文件处理页核对。
同名目录不一定属于该软件，配置目录可能包含账号、聊天记录、存档或其他个人数据；不会自动批量删除。
“清除失效记录”仅处理原卸载程序和目录已不存在的登记项，先在 data 中导出 .reg 备份，再删除那一个卸载列表键；不会模糊清理注册表，也不删除 MSI/系统组件记录。
32 位记录的备份，恢复时应使用 32 位注册表视图；可用 Windows reg import 文件路径 /reg:32。64 位用 /reg:64。无需清理时不必使用此功能。

【文件被占用时】
进入“文件解锁”，选择文件或文件夹，或拖到页面上的目标区域。
1. 点“检查占用”，查看占用程序、进程编号。
2. 优先“正常退出选中程序”，在对应程序里处理保存提示。
3. 确认没有需保存的内容后，才用“高级处理”中的“强制结束选中程序”。会再次核对进程身份。
4. 优先“移到回收站”。如果 Windows 提示无法回收，可取消。
5. 确认不需要恢复时可用“高级处理”中的“永久删除”；只读文件属性会在该操作中解除。
6. 仍受系统/驱动占用时，可以管理员模式在“高级处理”中登记“重启后删除”。它调用 Windows 的待重启删除机制，不会立即重启电脑。

重要行为：
永久删除、重启后删除、强制结束进程需要输入“确认”。完整目标路径会先展示。
重启后删除不经过回收站；当前版本不提供撤销登记入口。登记成功只表示 Windows 接收了请求，不能保证重启后全部成功。
如果只登记了部分项目，会明确报告部分成功、部分失败。重启前新产生的文件不在原计划里，可能使目录保留下来。
不会强关系统进程、结束整棵进程树、强行关闭内核句柄、修改文件所有者或接管系统目录权限。
文件占用检测使用 Windows Restart Manager，最多检查目标内 10,000 个文件，并补充从该目录运行的进程。
驱动、文件夹句柄、无权限项或过大的目录可能导致检查不完整；“没有找到”不代表没有占用。
拒绝磁盘根目录、用户资料根目录、共享软件根目录、系统保护区、当前程序目录、网络/设备路径和目录链接。
删除前会预检查目录树，永久删除只逐项删除已核对目标，不递归跟随联接点。遇到失败会保留失败原因，不报假成功。
任何删除都应在目标目录不再被其他软件修改时执行；直接删目录不能替代软件卸载，驱动或服务残留需由原卸载器处理。

【日志、备份和隐私】
所有扫描、导出、日志和注册表备份都留在本机，不上传、不遥测、不联网下载组件。
data/operations.log：操作与失败记录。
data/initial-scan.csv：交付验证时生成的原始扫描清单（包含未做界面去重的条目）。
data/scan-results.txt：本机扫描验证结果。
data/test-results.txt：自动测试结果。
日志和清单会包含本机软件与路径，分享前请核对。

【验证范围】
已用独立临时文件验证：实际占用进程定位、被锁文件删除失败报告、中文只读文件删除、边界与取消行为。
已只读验证本机的卸载记录、商店包和快捷方式来源。
交付时没有实际卸载现有软件、删除用户文件、结束用户程序或登记重启删除项。
重启删除、真实软件卸载和注册表删除没有对本机真实软件执行破坏性验收。

【源码】
src/ 保存完整 C# 源码；build.ps1 调用 Windows 自带 Framework 编译器生成可执行文件。
tools/make_icon.py 仅用于重建图标，运行程序不需要它或 Pillow。
不包含第三方强删驱动。未购买商业代码签名证书。

实现所依据的 Windows 官方接口：
Restart Manager: https://learn.microsoft.com/windows/win32/api/restartmanager/nf-restartmanager-rmregisterresources
重启删除: https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-movefileexw
