# 清理匣 CleanBox 2.1.9

Windows 软件发现、卸载与占用文件处理工具。补充系统卸载列表之外的程序候选，并帮助定位“文件正在使用，无法删除”的原因。

采用 C# / Windows Forms，面向 Windows 10/11 x64，依赖 .NET Framework 4.8。程序运行不需要 Python、Node.js 或额外的开发环境。

## 功能

2.1.9 修正拖动滑块时画面延迟、跳动和松手回跳。滚动位置改变后立即呈现内容与滑块，滑块按鼠标的连续位置绘制；拖动不再反复重排容器或枚举全部软件行。软件列表与滚动轨道缓存玻璃底图，减少每帧重绘；短列表使用当前字体和区域大小计算滚动范围，避免首次滚动改变滑块尺寸。深浅色同步处理，沿用 2.1.8 的原生滚动条裁剪方式。

界面自检新增可见窗口中的连续拖动检查：连续发送鼠标消息，在不松手、不手动生成截图的情况下，确认每步内容和滑块都收到实际绘制；同时检查逐像素跟随、松手位置和拖动期间的布局稳定性。隐藏启动的自检窗口会在这一步短暂显示，完成后自动关闭。旧版仅逐步截取画面的检查不能证明连续拖动时会及时刷新。

2.1.8 修正拖动时白底和悬停闪烁：移除 2.1.7 覆盖原生滚动条的实现，改用独立的圆角滚动控件，并将系统滚动条裁剪在内容视口之外。滑块自行处理拖动、轨道点击、滚轮和方向键 / 翻页键，悬停只改变颜色和滑块粗细，不改布局、不启动轮询重绘。软件列表、详情、文件占用列表、操作记录、残留候选、磁盘勾选列表和确认内容统一覆盖，横向滚动条与交汇角同步适配深浅色。无溢出时不显示滑块；辅助功能可读取和设置滚动位置，高对比度时使用系统强调色。

2.1.6 把每条软件记录改成独立的圆角玻璃条，保留行间空隙与圆角选中描边，表头也使用相同材质。跟光复用按钮的高光效果，只在鼠标所在行的圆角内部移动，不再铺在整张列表上；移到其他行或移出列表后清除旧光，滚动、排序与筛选仍保留原来的操作方式。

2.1.5 将软件列表和表头改为磨砂玻璃材质，增加随鼠标移动的柔光，移开后完整淡出。玻璃底图缓存复用，滚动时重新绘制，排序、选中和键盘操作沿用原有列表行为。Windows 11 标题栏、标题文字和外边框跟随深浅色主题，页面顶端使用相同颜色平滑衔接；较旧系统保留其支持的原生标题栏外观。

2.1 系列在三栏界面上加入磨砂玻璃面板、柔和背景、胶囊按钮、圆角输入框与统一菜单，并提供按钮轻按缩小、松手回弹。玻璃质感与弹性动效可分别在左下角关闭，设置在本机保存。深浅色外观与舒适 / 紧凑列表仍然可切换。

2.1.3 加强浅色模式的青蓝、淡紫折射与亮边。按钮高光通过弹簧跟随鼠标，按住时收紧、松手后回弹并扩散一层柔光；文字与点击区域保持固定。关闭弹性动效后高光立即跟随，关闭玻璃质感后不绘制跟光。原有的完整背景重绘与主题切换修复继续保留。2.1.4 修正跟光的静止亮度：鼠标移开后所有跟光层完整淡出，不在最后的位置留下光斑；关闭动效时立即清除。

2.1.2 修复实际窗口中的按钮黑底和残影：Windows 会跳过不透明按钮的独立背景绘制，因此按钮现在在同一绘制帧中完成背景与内容。新增真实 `WM_PAINT` 消息检查，已在 2.1.1 上复现缺失背景、在修复版上验证。此前手动调用背景绘制的测试未覆盖这条路径，现已更正。按钮文字保持固定大小和位置，页面与列表不随弹簧动画移动，详情面板不再闪亮。

玻璃是针对应用自身背景的合成材质；使用缓存背景和模糊层，动画停止后不持续刷新。小窗口会收起版本列，版本仍可在右侧查看。视觉方向参考 [FlClash 的玻璃与 Apple 风格交互更新](https://github.com/chen08209/FlClash/releases)，实现代码由本项目自行编写。

| 功能 | 具体行为 |
| --- | --- |
| 软件清单 | 读取 32/64 位全机与当前用户卸载记录、当前用户商店 / MSIX 包、开始菜单与桌面快捷方式 |
| 磁盘发现 | 扫描指定文件夹或所选固定磁盘中的 EXE，显示未登记的程序候选，支持取消 |
| 检索与导出 | 按名称、发布者、路径搜索，按来源筛选，导出 CSV |
| 正常卸载 | 调用原卸载器、Windows Installer 或当前用户的 AppX 卸载接口 |
| 残留检查 | 列出安装位置及名称完全匹配的配置目录，由用户逐项核对 |
| 失效记录 | 对符合条件的卸载列表项先导出 `.reg` 备份，再删除该项 |
| 占用检查 | 使用 Windows Restart Manager 查询文件占用，并补充从目标目录运行的进程 |
| 文件处理 | 回收站、永久删除、重启后删除；可对核实身份的普通进程请求退出或强制结束 |

程序发现项不会自动触发卸载或删除。永久删除、重启后删除及强制结束需要再次确认；系统目录、共享根目录、程序自身、目录联接与关键进程设有保护。

## 使用

1. 在 [GitHub Releases](https://github.com/charm-xr/tool/releases/tag/cleanbox-v2.1.9) 下载 Windows x64 安装版或便携版，页面提供各自的 SHA-256 校验文件。
2. 安装版双击 `CleanBox-Setup-Windows-x64.exe`，按向导选择位置和快捷方式。安装后可从开始菜单启动，也可在 Windows 的“已安装的应用”中卸载。便携版解压到有写入权限的文件夹后，双击 `CleanBox.exe`。
3. 启动后查看基础扫描结果。展开右上角“扫描软件”，使用“全盘发现”或“扫描指定文件夹”补充绿色软件候选，也可导出当前清单。
4. 软件选中后在右侧查看详情，优先使用“正常卸载”；对已确认的残留或被占用文件，进入左侧“文件解锁”。
5. 文件页先选择或拖入目标，再检查占用并请求程序退出。永久删除、重启后删除和强制结束位于“高级处理”。

快捷键：`Ctrl + F` 搜索软件；`F5` 基础扫描；`Esc` 取消当前可取消的任务。主题和列表密度可在左下角切换，管理员模式也位于左下角。

一般扫描无需管理员权限。受限的文件操作和重启删除需要通过界面切换到管理员模式。

详细操作见 [使用说明](使用说明.txt)。

## 扫描与删除的边界

- 不保证识别所有软件。磁盘发现以 EXE 为候选依据，可能包含辅助程序；纯脚本、DLL、压缩包和未挂载磁盘不作为独立软件自动识别。
- 不加载其他用户的离线注册表，也不读取其他用户的商店注册。
- 跳过系统保护区、无权限目录、目录链接，以及 `.git`、`node_modules`、`.venv`、`__pycache__` 等目录。
- 占用检查最多登记 10,000 个文件。驱动、目录句柄、权限限制等可能使检查不完整；未找到进程不代表没有占用。
- 直接删除目录不能代替完整卸载；服务和驱动应由原卸载器处理。
- 重启后删除使用 Windows 的待重启删除机制，需要管理员权限。登记后本工具不提供撤销入口，实际结果应在重启后核对。
- 不包含内核强删驱动，不修改文件所有者，也不强行关闭系统句柄。

## 本地构建

在 Windows PowerShell 或 PowerShell 中，从仓库目录运行：

```powershell
.\build.ps1
```

构建脚本使用 Windows 自带的 Framework C# 编译器，输出 `CleanBox.exe`。需要机器上存在 `.NET Framework 4.8` 及其 Framework 编译器；无需安装 .NET SDK 或还原第三方运行库。

已提交应用图标，因此普通构建不需要 Python。只有重新生成图标时才需要 Pillow：

```powershell
python -m pip install Pillow
python .\tools\make_icon.py
```

## 验证

运行核心测试：

```powershell
$test = Start-Process .\CleanBox.exe -ArgumentList '--self-test' -Wait -PassThru
if ($test.ExitCode -ne 0) { throw 'Core tests failed' }
Get-Content .\data\test-results.txt
```

测试在程序目录的 `tests/run-*` 中创建专用样例，覆盖路径保护、真实目录联接、中文只读文件、取消行为、实际文件锁定进程识别及删除失败报告。只清理专用测试文件，不卸载软件、不操作重启删除队列。

其他检查：

```powershell
# 读取当前机器的软件来源并生成本地报告
Start-Process .\CleanBox.exe -ArgumentList '--scan-report' -Wait

# 程序自身的界面检查，生成本地预览
Start-Process .\CleanBox.exe -ArgumentList '--ui-check' -Wait

# 指定一个包含 EXE 的已知软件目录，验证磁盘发现（不会运行候选程序）
.\tools\verify-discovery.ps1 -ScanPath 'C:\Example\PortableApp'
```

核心检查和本机界面检查已通过。真实软件卸载、注册表删除和重启删除没有对开发机器上的真实软件执行破坏性验收。

## 打包

```powershell
.\tools\package.ps1
```

安装版使用 Inno Setup 6.7 构建。运行 `.\tools\build-installer.ps1` 会校验 `downloads/` 中的便携包，将相同的程序文件封装为 `release/CleanBox-Setup-Windows-x64.exe`，并生成 SHA-256 文件。可用 `-ArchivePath` 指定另一个带校验文件的便携包。

输出 `release/CleanBox-Windows-x64.zip` 和 SHA-256 校验文件。打包采用文件白名单，仅包含程序、运行配置、图标、许可证和文档。

仓库根目录的 GitHub Actions 工作流会在 Windows 上执行构建、核心测试和打包，并上传最新构建产物。`downloads/` 提供由维护者单独更新的已打包版本。

## 数据与隐私

扫描结果、日志、注册表备份和界面预览仅保存在本机。应用本身不上传这些数据，不包含遥测或自动下载组件。

以下目录不进入 Git 历史或发布包：

- `data/`：软件清单、路径、日志、注册表备份与测试结果。
- `preview/`：可能包含真实软件清单的界面预览。
- `tests/`：运行时测试文件。
- `release/`：本地打包暂存目录与产物。
- `backups/`：本地升级前的程序和源码备份。

分享问题时请先清理日志中的个人路径、账号、软件列表等信息。
